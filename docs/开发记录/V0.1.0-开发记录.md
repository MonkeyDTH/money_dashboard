## 3. 设计决策记录

### 3.1 前端技术栈选 SSR + HTMX，不用 React/Vue

明确以"月底录入"为主要场景，交互复杂度低，SPA 的收益不值得引入构建链和前后端分离的维护成本。Tailwind CDN 省去构建步骤，代价是无法使用 JIT 任意值，实际开发影响极小。

### 3.2 双视图用 URL 参数而非前端状态

`?view=family/personal` 服务端渲染，而非 Alpine.js 在前端切换。好处是可书签、可分享，且图表数据完全独立计算，不存在前端状态残留的风险。

### 3.3 历史数据导入用一次性脚本而非改造导入路由

Excel 格式与系统导出格式完全不同，强行复用导入路由会增加不必要的兼容逻辑。独立脚本更易审查、执行一次即可，不需要长期维护。

### 3.4 账户列表 HTMX 局部刷新改为整页刷新

初始设计是 HTMX 增删改后只刷新账户表格 partial。实际实现时，账户列表需要分组渲染（家庭/个人），partial 无法独立承载分组标题，最终改为 POST 后返回整个 list 页面，简化了逻辑。

## 4. 遇到的问题及解决

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 首页图表全部空白，ECharts 实例未挂载 | Jinja2 默认 HTML 转义，将 JSON 中的 `"` 转为 `&#34;`，导致 JS 拿到非法数据 | 对所有传入 JS 的 JSON 模板变量加 `\| safe` 过滤器 |
| 所有页面返回 500，`TemplateResponse` 报 `unhashable type: 'dict'` | Starlette 1.0 将 `TemplateResponse` 签名改为 `(request, name, context)`，旧式 `(name, context)` 中 request 被当作模板名传入 | 将所有路由的 `TemplateResponse` 调用改为新签名，同时将 `Jinja2Templates` 实例统一到 `app/deps.py`，避免各路由重复实例化导致过滤器丢失 |
| Alembic 初次迁移执行失败，`NameError: name 'sqlmodel' is not defined` | Alembic autogenerate 生成的迁移文件未自动 import sqlmodel | 在生成的迁移文件顶部手动添加 `import sqlmodel.sql.sqltypes` |
