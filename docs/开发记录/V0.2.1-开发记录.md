## 3. 设计决策记录

### 3.1 明细更新策略：清空重建而非逐条 diff

编辑提交时删除全部旧 `SalaryItem` 再重新写入，而非对比新旧条目逐条增删改。

原因：明细条目无稳定业务主键（类型可重复、顺序可变），diff 逻辑复杂且收益低；清空重建对 SQLite 小数据量无性能问题，且代码与新建路由完全对称。

### 3.2 复用 form.html 而非新建编辑模板

通过 `{% if record %}` 判断在同一模板内切换新建/编辑模式，避免两份模板逻辑分叉。

### 3.3 direction 字段通过隐藏 input 传递

表单中可见的 `<select>` 通过 Alpine.js `x-model` 同步到隐藏 `<input type="hidden">`，后端统一读隐藏字段，保持了与新建逻辑的一致性。
