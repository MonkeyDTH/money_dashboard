# 薪资记录编辑功能

**日期**：2026-05-26
**状态**：设计稿，待实现

---

## 一、背景与动机

录入薪资数据后发现有误，但目前只有新增和查看功能，无法修改已录入的记录。需要增加编辑功能，允许修改薪资记录的基本信息和明细条目。

## 二、方案设计

### 核心逻辑

复用现有的 `form.html` 模板，通过传入 `record` 和 `items` 数据来区分新建（`record=None`）和编辑模式。

编辑时的处理策略：**删除旧明细，重新写入新明细**（最简单可靠，避免逐条 diff）。

### 数据流

```
GET  /salaries/{id}/edit  →  读取 record + items，渲染 form.html（编辑模式）
POST /salaries/{id}       →  清空旧 SalaryItem，重建，更新 SalaryRecord
```

### 关键决策

- `form.html` 的 `<form action>` 根据是否有 `record` 动态切换（`/salaries` 或 `/salaries/{record.id}`），method 统一用 POST，通过隐藏字段 `_method=PUT` 模拟 PUT，或者直接用独立 POST 路由（更简单）。
- 采用**独立 POST 路由** `/salaries/{id}/edit`（POST），不引入 method override，更直观。
- Alpine.js 初始化时用服务端渲染的 `initial_items` JSON 填充 `items` 数组，实现编辑态回填。

## 三、代码变更清单

| 文件 | 变更内容 |
|------|---------|
| `app/routers/salaries.py` | 新增 `GET /salaries/{id}/edit` 路由（渲染编辑表单）；新增 `POST /salaries/{id}/edit` 路由（处理更新，清空旧明细重建）|
| `templates/salaries/form.html` | 编辑模式支持：`action` 动态切换、基本字段回填、Alpine.js `initialItems` 数据回填 |
| `templates/salaries/detail.html` | 页头新增"编辑"按钮，链接到 `/salaries/{id}/edit` |
| `templates/salaries/list.html` | 每行操作区新增"编辑"入口（可选，按现有 UI 风格判断） |

## 四、验证方式

1. 进入某条薪资详情页，点击"编辑"按钮，表单应回填原有数据（年月、公司、成员、各明细条目）。
2. 修改某个明细金额后提交，详情页应显示更新后的数值，gross/net 重新计算正确。
3. 删除一个明细条目后提交，该条目应从数据库消失。
4. 新增一个明细条目后提交，该条目应出现在详情页。
5. 修改备注、发薪日后提交，详情页应反映变更。
